## 2. 设计：单一配置源

`gateway.json` 增加：

```json
{ "models": { "mode": "allowlist", "expose": ["deepseek-v4.1-flash"] } }
```

`mode` = `all`（默认）或 `allowlist`。三处共用（同一 `readModelsConfig`）：

| 消费方 | 行为 |
|---|---|
| `GET /v1/models` | 只返回暴露集合，响应带 `workbuddy_exposed: {mode,exposed,total[,allowlist,missing]}` |
| `POST /v1/chat/completions` | 未暴露 → `404`，`error.code="model_not_found"` + `workbuddy_reason_code="model-not-exposed"` |
| `install-provider` | 只写暴露集合进 `providers.workbuddy.models[]` |

- **策略过滤 ≠ 安全边界**（README/protocol 均写明）：能访问回环网关者已持有 bearer。
- 空 allowlist 被拒绝（会隐藏全部模型，且让 install 写空 provider）；`models all` 恢复。
- **幂等联动**：`models set/add/remove` 后，若 `models.json` 已装 `providers.workbuddy` → **自动同步**（同一次调用重写那段）；未装 → 输出提示“需重跑 install-provider”（`sync:` 行）。

CLI：
```
models list | set <id...> | add <id> | remove <id> | all      [--json] [--dry-run] [--api-key-env NAME] [--models-json P]
serve --models a,b            # 仅本次进程覆盖，不落盘
install-provider --models a,b # 仅本次进程覆盖，不落盘
```
非法 id（不在目录里）→ `model-unknown`，报错并**列出候选**（saved 目录；`serve --models` 也校验 saved 目录）。

## 3. 端口策略

解析顺序：`--port` > `WORKBUDDY_GATEWAY_PORT` > `gateway.json.port` > 默认 **8799**。

- 默认由 `8317` 改为 `8799`（8317 是本机 EasyCLIProxyAPI 的端口，**不再作为我们的期望值**）。
- **占用则自动挑空闲端口**：`listen()` 先做**主动 connect 探测**，被占用时改 `listen(0)`；Windows 上两个进程可绑同一端口，仅靠 `EADDRINUSE` 不可靠，故用探测。
- 显式 `--port` 被占用 → **明确报错**（原因码 `port-unavailable`，不再抛裸 `EADDRINUSE`；S-3），不悄悄改口。
- 实际端口/baseUrl/pid/startedAt 写入 `endpoint.json`（`baseUrl: http://127.0.0.1:<port>/v1`）。
- `install-provider` 的 `baseUrl` 默认读 `endpoint.json` 的实际端口（进程存活才采信）→ `gateway.json.port` → 默认；显式 `--port`/env 优先。
